# DJ Set Mastering Tool — Design

> The tool was called `djmaster` (repository `dj-master`) until it was renamed
> `fadercut` on 2026-10-11. Older sections below keep the names of their time.

**Date:** 2026-06-15
**Status:** Approved (revised — see Revision 1)

## Revision 1 (2026-06-15): transparent chain, no time-varying gain

The first chain used `dynaudnorm` (a time-varying leveler) before loudnorm. On real
material this **ducked the audio after loud transients and punched audible holes**
into quiet breakdowns (confirmed: a genuine ~4 s breakdown at 3077–3081 s was turned
into a near-silent hole). User constraint: *drops (silent→loud) are fine, but
loud→silent fast (when the track isn't actually silent) is very noticeable; only
adjust when imperceptible.*

A leveler fundamentally violates this — it rides program volume up/down. **Decision:
remove all time-varying program gain.** New chain = one constant gain + a look-ahead
peak limiter that only acts on peaks above the ceiling and recovers to unity gain.
This tames the reverb spikes (the original problem) while leaving the music's
dynamics — and breakdowns — untouched. Sections below reflect this revision.

## Problem

DJ sets recorded by the user have inconsistent perceived loudness section-to-section,
and reverb causes volume spikes that make simple peak-normalization ineffective (the
spike pins the ceiling while the rest of the set stays quiet). Goal: a **reusable**
program that produces an even, loud-but-clean master without audible quality loss.

## Goals / Non-goals

- **Goal:** consistent perceived loudness across the whole set.
- **Goal:** tame reverb/transient spikes so they don't dominate normalization.
- **Goal:** hit a configurable loudness target with a true-peak ceiling (no clipping).
- **Goal:** reusable CLI with presets; original file never modified.
- **Non-goal (now):** MP3/other-format export, GUI, EQ/multiband, batch folders.
  (Presets are structured so MP3/streaming can be added later without rework.)

## Revision 2 (2026-06-15): engineer-style gain riding (opt-in `--leveling`)

The transparent chain (Revision 1) only tames peaks; it does not even out the
~3.3 LU section-to-section swing the set actually has. To address that without the
artifacts, added an opt-in leveling mode modelled on how a mastering engineer works
(ride the fader by section *before* limiting) and on iZotope RX's two-module split
(time-varying Leveler + fixed-gain Loudness Control).

Algorithm (all DSP in pure NumPy, ffmpeg only decodes/measures/encodes):
1. **Analyze** EBU R128 short-term (S) + momentary (M) loudness timeline (`ebur128`
   + `ametadata` print, ~10 Hz).
2. **Gain-ride** — `leveler.compute_gain_db`: pull each section toward the *average*
   section loudness (loudness-neutral / variance-reducing), with BS.1770-style
   gating (freeze gain where M is >gate LU below program loudness — protects
   breakdowns/drops), partial strength (~0.6), a ±dB clamp, and slew-rate limiting
   (structurally prevents pumping and fast loud→quiet moves).
3. **Apply** the envelope by streaming f32le through NumPy (`apply.apply_envelope`),
   then a post filter: optional glue compression (strong only), make-up gain, and
   the true-peak limiter.

Modules added: `analysis.py`, `leveler.py`, `apply.py`. New dependency: NumPy
(leveling path only). Profiles: `gentle`, `strong`. Default remains `--leveling off`
(the Revision 1 transparent chain).

## Revision 3 (2026-06-15): asymmetric leveling (`--preserve-loud`)

The symmetric leveler pulled loud sections down to even them out, which flattened the
set's intentional energy build (the loud finale was cut ~1 dB). User wants the loud
sections preserved and only the quiet ones lifted. Split `strength` into
`up_strength` (boost quiet) and `down_strength` (cut loud); `--preserve-loud` sets a
low `down_strength` (0.15) so loud sections/drops/climax are barely touched while
quiet sections are lifted fully. Consequence: overall loudness rises slightly (we
lift rather than lower); peaks still capped by the limiter. Recommended for DJ sets.

## Revision 4 (2026-06-15): intro/drop exemption + masked smoothing

The leveler over-boosted the opening intro (it reads as "quiet" because it builds in)
and drifted ~1.8 dB down over the following steady bars — a mild loud→quiet drift on
steady music. Fixes in `compute_gain_db`:
- **Masked smoothing** (`_masked_moving_average`): section loudness averages over
  *foreground* frames only, so silence/breakdowns don't drag the level down.
- **Onset hold** (`onset_hold_s`, ~4 s): material is only leveled once it has been
  continuously foreground for the hold time; onsets emerging from silence (intros,
  drops) hold the prior gain — honours "silent→loud is left alone".
- **Leading-intro exemption** (`_INTRO_MARGIN_LU`): gain is held at 0 dB through the
  opening build until the groove first reaches program level, so the intro comes in
  at its natural level. Verified: intro 0:29–0:33 now sits at +0.0 dB; mid-set lifts
  and the finale are unchanged.

## Revision 5 (2026-06-15): club low-end, preview mode, faster renders

- **Club low-end** (`--bass-mono [HZ]`, `--subsonic [HZ]`): subsonic high-pass
  (default 28 Hz) frees headroom; bass-mono (default <120 Hz) folds lows to mono via
  an LR4 band split (low band summed to mono, high band kept stereo) so the low end
  translates on mono-summed club rigs. Implemented as a `filter_complex` graph
  (`chain.build_graph`) used by both the transparent render and the leveling encode;
  the simple `-af` paths are unchanged when low-end is off. Verified: side energy
  below 120 Hz dropped ~11 dB.
- **Preview mode** (`--preview START-END`): processes only a time range (clip threaded
  through every decode via `ffutil.clip_args`) so a setting can be auditioned in ~1 s
  instead of minutes. Output goes to `<stem>-preview.wav`.
- **Faster renders**: the leveling path derives its before-stats from the ebur128
  timeline (now captures true peak + LRA via `peak=true`) instead of a separate
  loudnorm pass — one fewer full-file decode (3 passes → 2).

## Revision 6 (2026-10-11): Rust port

The app was ported from Python to Rust as a behaviour-faithful rewrite, ahead of the
mastering fixes in `2026-10-11-mastering-fix-plan.md`. Same CLI, same filter strings,
same algorithm; the rendered audio is byte-identical to the Python version across 13
flag combinations on a 4.7-minute test set.

Layout: `src/main.rs` (entry), `cli.rs` (arguments), `pipeline.rs` (orchestration),
`presets.rs`, `chain.rs` (filter strings), `loudness.rs` + `analysis.rs` (ffmpeg
measurement and parsing), `leveler.rs` (gain ride), `apply.rs` (streamed envelope),
`ffutil.rs`, `error.rs`. Unit tests live beside the code; `tests/cli.rs` runs the
binary end to end.

Intentional deviations from the Python behaviour:
- The leveling path's "before" true peak is now correct (ebur128 reports linear
  amplitude; it was being printed as dB).
- `--bass-mono` / `--subsonic` reject frequencies that are not greater than 0.
- A silent or unmeasurable input fails with a clear error instead of an ffmpeg one.
- ffmpeg child processes no longer inherit stdin, so they cannot consume keystrokes
  or piped input meant for the shell.
- A failed encoder during leveling reports `encode ffmpeg failed` instead of an
  unhandled broken-pipe traceback.

## Revision 7 (2026-10-11): measured mastering chain

Implements `2026-10-11-mastering-fix-plan.md`. The chain is now:

```
[subsonic high-pass] -> [bass-mono] -> volume (constant gain) -> [limiter]
```

- **Limiter.** `asoftclip` is gone (it shaped the whole signal: 2.4 % THD on a sine
  peaking at -6 dBFS). The limiter is `alimiter` run at >= 176.4 kHz between two
  `aresample` stages, with `latency=1`, so it limits inter-sample peaks. Release is
  100 ms; `asc` was dropped because it had no measurable effect. The limiter is left
  out of the graph when the gained peaks stay under its threshold, which keeps
  quiet targets a pure gain change.
- **Landing loop** (`landing.rs`). Each render is measured; loudness error is added
  to the gain and a true-peak overshoot is taken off the limiter threshold, then it
  renders again (at most 4 passes, accepted within 0.3 LU and 0.05 dB). The decision
  logic is pure and the renderer is injected. A render that still exceeds the
  ceiling is an error; one that only misses loudness is written with a warning.
- **Limiter cost.** An `ebur128` tap ahead of the limiter gives the loudness of the
  signal entering it; minus the loudness of the finished file, that is what the
  limiter removed. Reported on every run, with a warning above 0.7 LU. Crest factor
  was tried first and rejected: it missed the extra limiting caused by the low-end
  filters' phase rotation.
- **One tail.** `chain::master_filter` builds the graph for every path, so
  `--bass-mono` / `--subsonic` no longer change what follows them.
- **Glue compressor removed.** Its threshold was absolute, so the amount depended on
  recording level (2.3 LU on the test set, 0.5 LU on the same set 6 dB quieter), and
  a second bus compressor over already-mastered tracks was not solving a stated
  problem. `strong` leveling is now only a stronger ride.
- **Measurement.** `loudnorm` analysis was replaced by `ebur128` everywhere (about
  six times faster, and it is the same meter the leveler already used).
- **Atomic output.** Renders go to `<name>.partial-<pid>.wav` and are renamed into
  place only after the ceiling check passes.

Not changed: the `club` preset is still -9 LUFS / -1 dBTP and still the default.
The plan proposed a -2 dBTP ceiling for it; measurement showed that costs 1.5 LU of
limiting on the test set, so it was not applied. Offered −11 or −14 as the default
instead, the owner chose to keep −9. The Python sources were deleted after the port.

## Revision 8 (2026-10-11): Audacity projects as input

The owner works in Audacity 4 and did not want to think about export settings, so
fadercut reads `.aup3` / `.aup4` projects directly (`src/aup/`).

- **Format.** A project is an SQLite database: `project(dict, doc)` holds the
  project XML in Audacity's binary serialization (`ProjectSerializer`), and
  `sampleblocks` holds the audio. `aup/xml.rs` decodes the document (including the
  `FT_Blob` field Audacity 4 added); `aup/layout.rs` turns it into a mixdown plan;
  `aup/render.rs` mixes blocks to interleaved stereo with one decoded block per
  clip in memory. The decoded layout was checked against Audacity's own source
  (`WaveTrack.cpp`, `WaveClip.cpp`, `Sequence.cpp`) for stereo linking, pan law,
  trims and rounding.
- **Read-only by construction.** Opened with `mode=ro&immutable=1`, which takes no
  locks and creates no `-wal`/`-shm`/journal files. Immutable mode cannot see a
  write-ahead log, so a project with a `-wal` or `-shm` beside it (open in
  Audacity) is refused instead of being read stale.
- **Scope.** Everything Audacity renders that we reproduce exactly is supported:
  multiple tracks, mute/solo, volume, pan, multiple clips with offsets and trims,
  silent blocks, 16/24-bit and float blocks. Anything else that changes the audio
  (stretch, pitch, realtime effects, time track, mixed rates — and, until
  Revision 9, envelopes) is an error naming the feature, not an approximation.
- **Integration.** The mixdown is written once to a float WAV beside the output
  (RF64 past 4 GB) and the existing pipeline runs on it unchanged; a preview range
  is applied during the mixdown so only that range is read.
- **Verification.** On a real 96 kHz Audacity 4 project the rendered audio was
  bit-identical to an independent decode of the database, and the project's SHA-1,
  size, mtime and directory listing were unchanged. A 66-minute project mixes down
  in a few seconds.

## Revision 9 (2026-10-11): clip volume envelopes

The owner fixed a transition by layering a short clip on a second track and drawing
a volume envelope on it; the project was refused. Envelopes are now applied
(`src/aup/envelope.rs`).

- **Curve.** As in Audacity's `Envelope::GetValuesRelative` for a wave clip
  (`mDB = true`): the first point's gain is held before it, the last point's after
  it, and between two points the gain moves linearly in log10, i.e. a straight line
  in decibels. Two points at one time are a step.
- **Clock.** Point times count from the clip's stored audio (`offset`), trimmed or
  not. A played frame's time is its timeline position minus `offset`, with the play
  start snapped to a sample as `WaveClip::GetPlayStartTime` does.
- **Order.** The envelope multiplies the samples before track volume and pan, as in
  `MixerSource`.
- **Known difference.** Audacity lets a step take effect up to half a sample early
  (its `epsilon`); here it lands on the first frame at or after its time. At most
  one sample at a drawn discontinuity.
- **Unchanged.** A clip without an envelope, or with one that stays at unity, is
  still a plain copy of its samples.
- **Verification.** Unit and end-to-end tests against the curve computed
  independently. On the owner's project (three tracks, a five-point envelope) the
  render of the enveloped passage matched a separate Python reimplementation to
  -131 dB. Against Audacity 4.0.1's own 32-bit float export of that project (63.6
  minutes, 96 kHz) the mixdown is bit-identical up to the envelope and differs by at
  most -144.5 dBFS from there on, which is float rounding. Audacity's export is one
  frame shorter at the very end.

The sections below describe the chain as originally designed and are kept as
history; module names in the "Architecture" section refer to the retired Python
layout.

## Processing chain (ffmpeg) — revised

```
volume (constant gain)  ->  alimiter (look-ahead peak limiter)
[set overall loudness]      [tame reverb/transient peaks only]
```

1. One measurement pass reads integrated loudness + true peak.
2. **`volume`** applies a single constant gain = `target_I − measured_I` (linear,
   zero pumping). For `even-only` the target *is* the measured loudness → gain ≈ 0.
3. **`alimiter`** (look-ahead, `level=disabled`, `asc=1`, attack 5 ms / release 60 ms)
   limits to the true-peak ceiling. It only attenuates while a sample exceeds the
   ceiling, then recovers to unity — so it cannot duck quiet passages or create holes.

No `dynaudnorm`, no time-varying program gain (see Revision 1). Output: 24-bit WAV
(`pcm_s24le`), same sample rate as source.

## Presets

| Preset      | Integrated (I) | True Peak (TP) | LRA | Notes |
|-------------|----------------|----------------|-----|-------|
| `club`      | -9 LUFS        | -1 dBTP        | 9   | Default. Loud hard-groove master. |
| `streaming` | -14 LUFS       | -1 dBTP        | 11  | SoundCloud/Spotify reference. |
| `even-only` | (measured)     | -1 dBTP        | 11  | Keep current loudness, just even out + tame spikes. |

Any preset value overridable via flags (`--target`, `--tp`, `--lra`).

## CLI

```
python djmaster.py "<input.wav>" [--preset club] [--target -9] [--tp -1]
                                  [--lra 9] [--output PATH] [--dry-run]
```
- Default output: `<input-stem>-mastered.wav` beside the input.
- `--dry-run`: print the ffmpeg commands + measured loudness, render nothing.
- Prints **before → after** Integrated LUFS, True Peak, LRA report.

## Architecture

```
dj-master/
  djmaster.py    # CLI: arg parse, validation, orchestration, report printing
  chain.py       # pure: build ffmpeg filter strings from a Preset/params
  loudness.py    # run measurement pass, parse loudnorm JSON, dataclasses
  presets.py     # Preset dataclass + named PRESETS dict
  tests/         # unit tests for pure logic (no audio/ffmpeg needed)
```

- **Separation of concerns:** pure filter/preset/parse logic (unit-tested) vs ffmpeg
  subprocess calls (isolated boundary in `loudness.py`/`djmaster.py`).
- **Reliability:** preflight checks ffmpeg present + input exists/decodes; never
  overwrites input; nonzero ffmpeg exit surfaces stderr; refuses to clobber existing
  output without `--output`.
- **Testability:** `chain.build_filter()`, `presets`, and `loudness.parse_loudnorm_json()`
  are pure functions tested without invoking ffmpeg.

## Error handling

- Missing ffmpeg → actionable message (`brew install ffmpeg`).
- Input missing / undecodable → fail fast with path + ffmpeg stderr tail.
- loudnorm JSON not found in stderr → raise with captured output.
- Output exists → refuse unless explicit `--output` / `--force`.

## Testing

- Unit: preset resolution, flag overrides, filter-string construction, JSON parse
  (including malformed input), output-path derivation.
- Manual integration: run on the real set, confirm report shows target hit (±0.5 LU)
  and TP ≤ ceiling.
